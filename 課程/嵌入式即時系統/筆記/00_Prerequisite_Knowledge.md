## 為什麼這個專案看起來很複雜？
---

如果你來自 Windows 或 Linux 開發背景，可能會感到不適應，原因有兩個核心差異：

**黑盒子 vs. 赤裸裸**：一般的 OS 會把核心 (Kernel) 藏起來，你只看得到 App 代碼。但在 uC/OS-II 中，**Kernel 原始碼與你的 App 躺在同一個資料夾**。

**上帝兼住戶**：你同時是 App 的開發者（住戶），也是系統環境的配置者（上帝）。一般開發者只做其中一件事，但在這裡必須同時做兩件。

## 邊界釐清：核心 vs. 使用者
---

為了不被代碼淹沒，用「角色與責任」的角度進行明確劃分：

| 類別 | 主要路徑（資料夾/檔案） | 你的角色 | 它的職責 |
| :--- | :--- | :--- | :--- |
| **核心地帶 (Kernel)** | `uCOS-II\SOURCE` | **觀察者** | 核心大腦（排程、計時、通信） |
| | `uCOS-II\Ix86L` | **觀察者** | 處理器移植層（暫存器操作） |
| | `BLOCKS\PC` | **觀察者** | 硬體模擬層（對應 DOS 功能） |
| | `bc45\` | **使用者** | 編譯工具鏈（翻譯機器） |
| | `SOFTWARE\TO\` | **使用者** | 目錄跳轉小工具（傳送門） |
| **使用者地帶 (User)** | `EXn...\SOURCE\TEST.C` | **創造者** | **應用程式邏輯（你的程式）** |
| | `EXn...\SOURCE\OS_CFG.H` | **上帝（配置者）** | **系統開關（控制 OS 功能）** |
| | `EXn...\SOURCE\INCLUDES.H` | **維護者** | 引用管理（專案標頭檔） |

> 記住這張表，往後看到任何陌生的檔案，先查它屬於哪個「類別」，再決定要不要深入研究。

## 作業系統架構：單一地址空間
---

uC/OS-II 採用**單一地址空間（Single Address Space）**與**平面模式（Flat Mode）**，與 Windows/Linux 的設計哲學大不相同：

**無特權區隔**：App 與 Kernel 跑在同一個特權等級。App 可以直接呼叫 Kernel 函數，例如直接寫 `OSSemPost()`，不需要透過系統呼叫（System Call）。

**直接接口**：你不需要 API 抽象層，你的程式碼是直接連動核心原始碼。這帶來更低的執行延遲，但也意味著一個 App 的 Bug 可能直接讓整個系統崩潰。

**靜態組合**：編譯時，OS 程式碼會直接「縫合」進你的 App。最後產出的 `.EXE` 是一個包含 OS 功能的單一實體，而不是 App 向 OS 借用功能。

## 編譯與環境的概念
---

### 交叉編譯 vs. 本地編譯

**交叉編譯（Cross-Compilation）**：在一個平台上，替另一個不同平台產生執行碼。以本課程的環境來說，我們在 Windows (64-bit) 上幫 DOS (16-bit) 製作程式，這就是交叉編譯的思維。

**本地編譯（Native Compilation）**：工具鏈與目標環境相同。如果在 DosBox 內執行 Borland C++ 編譯器，因為工具與執行環境都是 DOS，這在術語上稱為本地編譯。

### 模擬的本質

這個開發環境並非「模擬一個嵌入式硬體」，而是**「利用已知環境（DOS）當作硬體」**。`BLOCKS\PC` 資料夾裡的程式碼，利用 DOS 提供的中斷服務（計時器、鍵盤、顯示器）來替代真實嵌入式板子上的外設驅動，讓 uC/OS-II 就像跑在真實嵌入式板子上一樣。

## 系統特性：微核心架構
---

你可能會驚訝於 `SOURCE` 資料夾只有 11 個檔案。這是因為 uC/OS-II 是一個**微核心（Microkernel）**架構，設計哲學是「只做最核心的事」：

| 特性 | 說明 |
| :--- | :--- |
| **高度精簡** | 只負責排程、同步、時間管理。完整核心碼僅 ~20KB。 |
| **可裁剪性** | 透過 `OS_CFG.H` 關掉不用的功能（如 `OS_SEM_EN = 0`），編譯後的核心可能只有幾 KB。 |
| **確定性（Deterministic）** | 程式碼量少、邏輯清晰，所有操作的最壞執行時間（WCET）都可以預測。 |

它剔除了所有非必要的負擔：沒有圖形介面、沒有複雜的驅動資料庫、沒有內建檔案系統。這讓它能跑在記憶體只有幾十 KB 的極簡硬體上。

## 開發心法總結
---

掌握三個分層思考原則，往後閱讀程式碼時就不會迷失：

| 場景 | 你應該去哪裡找 |
| :--- | :--- |
| 需要修改應用程式邏輯 | `EXn...\SOURCE\TEST.C` |
| 想調整系統組態（任務數、tick 率） | `EXn...\SOURCE\OS_CFG.H` |
| 想理解排程或 IPC 的內部實作 | `uCOS-II\SOURCE\` |
| 想理解 x86 的 Context Switch 細節 | `uCOS-II\Ix86L\` |
| 想理解如何用 DOS 模擬硬體 | `BLOCKS\PC\` |
